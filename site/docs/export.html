Exporting to PDF, images, HTML and Typst

easy-math-lang writes the intermediate Typst source (doc.typ

next to your .ezmath), converts it with the typst package, then

removes the intermediates on success — only the deliverable stays.

Pick the output by extension — or explicitly with --format.

Quick examples

uv run easy-math-lang doc.ezmath              # doc.pdf (default)
uv run easy-math-lang doc.ezmath out.png      # PNG image(s)
uv run easy-math-lang doc.ezmath out.svg      # SVG image(s)
uv run easy-math-lang doc.ezmath out.html     # HTML page
uv run easy-math-lang doc.ezmath out.typ      # Typst source only (no render)
uv run easy-math-lang --format png doc.ezmath # doc.png
uv run easy-math-lang --format png --ppi 300 doc.ezmath -o hi.png
easy-math-lang --list-formats                 # pdf, png, svg, html, typ

typst is accepted as an alias of typ (--format typst, out.typst),

matching the "Typst" label used in the docs and the editor.

The installed binaries (easy-math-lang, ezmath) accept the same flags.

In the desktop editor: File → Export As… (PDF/PNG/SVG/HTML/Typst)

works for saved and untitled documents; PNG prompts for DPI (default 150).

Formats

FormatExtensionNotes
PDF.pdfDefault. Print-ready A4 document.
PNG.pngRaster image. --ppi 1..1200 controls resolution.
SVG.svgVector image (scales cleanly for slides/web).
HTML.htmlSingle web page (Typst HTML export).
Typst.typ (.typst also works)Intermediate source only — no typst.compile() call.

Multi-page images

PNG/SVG are one-file-per-page when the document spans pages.

doc.png with 3 pages writes doc-1.png, doc-2.png, doc-3.png

(the CLI prints the stem-{p}.ext pattern). To choose the pattern

yourself, include {p} in the output name: out-{p}.png.

Tips

  • Unknown extensions (e.g. out) warn and assume PDF — add --format

to be explicit.

  • Invalid --format/--ppi fails fast with exit code 2 and a hint.
  • Intermediates (.typ, .smap.json, -plot-*.svg next to

the input) are removed on success; pass --save-build-artifacts to

keep them for debugging layout. Failures always keep them. The

compile_ezmath() API and the editor preview always keep them.

*image files are your own sources, never intermediates: they are

never deleted, and typ/html exports to another folder copy them

along (preserving their relative layout) so the exported source

keeps working.

  • Geometry (*draw) renders identically in every format (CeTZ canvas).

Honest status and --strict

A document with [Error] diagnostics (undefined <variable>,

calc() division by zero, …) still writes the PDF by default and

exits 0 for backward compatibility — but the final line is honest:

Compiled doc.ezmath to doc.pdf with 2 error(s), 1 warning(s)

instead of Successfully compiled … via Typst! (clean builds keep

the success message). The PDF may contain inline markers like

[Calc Error: …] where evaluation failed.

Pass --strict to turn errors into a non-zero exit (the PDF is still

written when possible):

uv run easy-math-lang --strict doc.ezmath

Useful in CI to fail a build on typos and bad calculations.
