Easy Math Language
==================

Project goal
------------

This project aims to provide an easy coding environment for people who just
want a simple way to create math documents, projects, or lesson plans,
especially teachers.

The syntax should be kept as simple and readable as possible.

Comments
--------

"// text" is used for comments.

Definitions
-----------

*define(name = value)

Defines a reusable value.

Example:

*define(tmp1 = 100 000 000)

A defined value can be referenced directly using:

<tmp1>

When a variable is printed directly, it is treated as text.
It is NOT automatically calculated.

Example:

Code:
*define(tmp1 = 100 000 000)
<tmp1>

Output:
100 000 000


Variables
---------

<name> = value

Creates a variable.

Example:

*(
    <tmp1> = 2
    <tmp2> = 3
    <tmp3> = <tmp1> * <tmp2>
)

A variable can be inserted directly into normal text.

Example:

Code:
<tmp1> = 2
<tmp2> = 3
<tmp3> = <tmp1> * <tmp2>

Diện tích HCN là: <tmp3> = calc(<tmp3>)

Output:
Diện tích HCN là: 2 . 3 = 6


Calculation
-----------

calc(expression)

Calculates a mathematical expression.

It works similarly to eval() in Python, but only for mathematical
expressions.

Example:

Code:
<tmp1> = 2
<tmp2> = 3
<tmp3> = <tmp1> * <tmp2>

Diện tích HCN là: <tmp3> = calc(<tmp3>)

Output:
Diện tích HCN là: 2 . 3 = 6


Variables can also be defined using already existing variables.

Example:

Code:
*(
    <tmp1> = 2
    <tmp2> = 3
    *define(tmp3 = <tmp1> * <tmp2>)
    <tmp4> = calc(<tmp1> + <tmp2>)
)

Diện tích HCN là: <tmp3> = <tmp4>

Output:
Diện tích HCN là: 2 . 3 = 6


Printing
--------

*p(expression)

Prints something explicitly.

This is useful when normal syntax could conflict with the programming
language.

Example:

*p(f())

The expression inside *p() is printed instead of being interpreted as code.


Math syntax
-----------

All math commands use "*" as a prefix.

The "*" prefix prevents normal words from being interpreted as math commands.

Examples:

*frac(...)
*sqrt(...)
*sin(...)
*cos(...)
*sum(...)


Fractions
---------

*frac(numerator ; denominator)

Example:

*frac(2 ; 3)

Output:

2
─
3


Roots
-----

*root(index ; radicand)

Example:

*root(3 ; x + 1)

When compiling to Typst, braces should be added around the radicand when
necessary.

Example Typst output:

$root(3, {x + 1})$


Powers
------

*pow(base ; exponent)

Example:

*pow(x ; 2)

Output:

x²


Degree
------

*degree represents the degree symbol.

Example:

*pow(A ; *degree)

Output:

A°


Subscripts
----------

Use "_" for subscripts.

Example:

A_1

Output:

A₁


Absolute value
--------------

*abs(expression)

Example:

*abs(x - 2)


Trigonometric functions
-----------------------

*sin(x)
*cos(x)
*tan(x)
*cot(x)
*sec(x)
*csc(x)
*arcsin(x)
*arccos(x)
*arctan(x)
*sinh(x)
*cosh(x)
*tanh(x)
*coth(x)

All take one argument, like *sin(x). They also work inside *plot(...).


Integrals
---------

*int(expression)
*int(expression ; variable)
*int(lower ; upper ; expression)
*int(lower ; upper ; expression ; variable)

Example:

*int(0 ; 1 ; x^2 ; x)

Output (Typst):

$integral_0^1 x^2 dif x$

*oint(...) is the contour integral (Typst integral.cont) with the
same 1-4 arguments. *integral(...) is an alias of *int(...).


Piecewise and equation systems
------------------------------

*cases(row1 | row2 | ...)

Example:

*cases(x + y = 3 | x - y = 1)

Rows split on "|" (same quote/nesting rules as *matrix rows).
Inside a row, a depth-0 ";" (same rules as *matrix cells; "," works
when the row has no ";") separates value/condition cells, emitted
with Typst "&" alignment. Piecewise example:

*cases(x ; x > 0 | 0 ; x <= 0)

Multiline block form works too:

*cases(
    x + y = 3
    x - y = 1
)


Vectors (arrow accent)
----------------------

*vec(AB)

Arrow accent over the expression (Typst arrow, not a column vector).
Column vectors stay available through *matrix.


Binomial coefficients
---------------------

*binom(n ; k)

Example:

*binom(n ; k)

Output (Typst):

$binom(n, k)$


Logarithms
----------

*log(x)
*ln(x)


Summation
---------

*sum(lower ; upper ; expression)

Example:

*sum(i = 1 ; n ; i)

Output:

  n
  Σ i
 i=1


Product
-------

*prod(lower ; upper ; expression)

Example:

*prod(i = 1 ; n ; i)

Output:

  n
  Π i
 i=1


Limit
-----

*lim(variable -> value ; expression)

Example:

*lim(x -> 0 ; sin(x) / x)


Constants
---------

*pi

Output:

π


*infinity

Output:

∞


Operators
---------

The multiplication symbol can be customized.

*define(write_type.multiplication = .)

The default value can be "." because it is commonly used in Vietnam.

For example:

2 * 3

can be displayed as:

2 . 3

Other users may define it as:

*define(write_type.multiplication = x)

which displays:

2 x 3

General syntax rule
-------------------

Words without "*" are treated as normal text or language syntax.

Words beginning with "*" are treated as special commands or math symbols.

Examples:

alpha

means normal text.

*alpha

means the mathematical symbol:

α

This avoids conflicts between normal language and math syntax.

Inline math mode
----------------

\ expression \

Writes expression in mathematical mode (Typst math typography).

Example:

The solution is \ x = 2 \.

Output uses Typst math mode: $x = 2$.

Whitespace just inside the delimiters is ignored.

An unescaped \ opens math mode, the next unescaped \ closes it.
\\ is a literal backslash and never opens math mode.

Inside math mode, normal ASCII-friendly syntax works:

\ x <= y \
\ a^2 + b^2 = c^2 \
\ x -> infinity \

Existing replacements still apply inside math mode
(<= becomes ≤, -> becomes →, *alpha becomes α, ...).

Do NOT use LaTeX commands such as \leq or \rightarrow.
Just write <=, >=, !=, -> directly.

Math mode can span several lines: the first unescaped \ opens,
content on following lines is buffered until the closing \.

An unclosed \ produces a diagnostic (missing closing \).
Empty \ \ produces a warning and emits nothing.

Control lines (assignments, *define, *draw blocks) take precedence:
a line that is a control line is not treated as math, and while a
multiline math block is open, control lines are suspended.

Drawing and Geometry
--------------------

The language supports drawing basic geometric figures.

The drawing syntax should be simple and readable, so users do not need to
manually calculate coordinates for every point.

Points
------

*point(name)

Creates a point.

Example:

*point(A)
*point(B)
*point(C)


Points can also be defined with coordinates when exact positioning is needed.

*point(A = 0, 0)
*point(B = 4, 0)
*point(C = 2, 3)


Automatic point positioning
---------------------------

The drawing system should be able to determine point positions automatically
when enough geometric constraints are provided.

Users should not have to manually specify coordinates when they are not
important.

Example:

*point(A)
*point(B)

*line(A ; B)


Geometric relationships can be used to determine other points.

Example:

*point(A = 0, 0)
*point(B = 4, 0)

*point(C)
*on-circle(A ; 3 ; C)

The system can determine C from the given geometric constraints when possible.


Lines and segments
------------------

*line(A ; B)

Draws a line segment from A to B.

Example:

*line(A ; B)


A line can also be defined using a geometric relationship.

*line(A ; B ; infinite)

Draws an infinite line through A and B.


Rays
----

*ray(A ; B)

Draws a ray starting at A and passing through B.


Circles
-------

*circle(center ; radius)

Draws a circle.

Example:

*circle(O ; 3)


A circle can also be defined using a point on the circle.

*circle(O ; A)


Arcs
----

*arc(center ; start ; end)

Draws an arc.

Example:

*arc(O ; A ; B)


Angles
------

*angle(A ; B ; C)

Draws an angle arc marker at vertex B.

Example:

*angle(A ; B ; C)


An angle can optionally have a label.

*angle(A ; B ; C ; 60°)


Right angles
------------

*right-angle(B ; A ; C)

Draws a right-angle marker.

Example:

*right-angle(B ; A ; C)

Draws a right-angle marker at vertex A (arms toward B and C).

Convention: the middle argument is always the vertex.


Equal angles
------------

*equal-angle(A ; B ; C ; D ; E ; F)

Marks two angles as equal.

[planned — not yet implemented]

Example:

*equal-angle(A ; B ; C ; D ; E ; F)


Parallel lines
--------------

*parallel(A ; B ; C ; D)

Marks AB and CD as parallel.

Example:

*parallel(A ; B ; C ; D)

Output:

AB ∥ CD


Perpendicular lines
-------------------

*perp(A ; B ; C ; D)

Marks AB and CD as perpendicular.

Example:

*perp(A ; B ; C ; D)

Output:

AB ⊥ CD


Triangles
---------

*triangle(A ; B ; C)

Draws triangle ABC.

Example:

*triangle(A ; B ; C)


A triangle can also include labels.

*triangle(A ; B ; C ; labels)


Side marks
----------

*equal-length(A ; B ; C ; D)

Marks AB and CD as having equal length.

Example:

*equal-length(A ; B ; C ; D)


Point labels
------------

Point labels are displayed automatically.

Example:

*point(A)
*point(B)
*point(C)

*triangle(A ; B ; C)

The system automatically places the labels so they do not overlap the
geometric figure when possible.

Text labels
-----------

*label(point ; text)

Adds a custom label near a point.

Example:

*label(A ; A)
*label(B ; B)
*label(C ; C)


Measurements
------------

Lengths and angles can be displayed as labels.

Example:

*length(A ; B)

*angle-value(A ; B ; C)


Example:

*length(A ; B) = 5
*angle-value(A ; B ; C) = 60°


Coordinate system
-----------------

Coordinates are optional.

For simple geometric figures, users should be able to describe relationships
instead of specifying exact coordinates.

Example:

*point(A = 0, 0)
*point(B = 5, 0)

*line(A ; B)

*point(C)
*perp(A ; B ; C)

The drawing engine attempts to determine the position of C automatically.


Constraints
-----------

Geometric constraints can be used to determine point positions.

Examples:

*on-line(A ; B ; C)

C lies on line AB.


*on-circle(O ; 5 ; A)

A lies on the circle with center O and radius 5.


*distance(A ; B ; 5)

AB has length 5.


*perp(A ; B ; C ; D)

AB is perpendicular to CD.


*parallel(A ; B ; C ; D)

AB is parallel to CD.


*midpoint(A ; B ; C)

C is the midpoint of AB.


Intersections
-------------

*intersection(name ; object1 ; object2)

Creates a point at the intersection of two geometric objects.

Example:

*intersection(C ; line(A ; B) ; line(D ; E))


The position of C is calculated automatically by the drawing engine.


Drawing blocks
--------------

Multiple drawing commands can be grouped together using *draw(...).

Example:

*draw(
    *point(A = 0, 0)
    *point(B = 5, 0)
    *point(C = 2.5, 4)

    *triangle(A ; B ; C)

    *angle(B ; A ; C)
    *angle(A ; B ; C)

    *equal-length(A ; B ; A ; C)
)


Example: right triangle
-----------------------

Code:

*draw(
    *point(A = 0, 0)
    *point(B = 4, 0)
    *point(C)

    *distance(A ; C ; 3)
    *perp(A ; B ; A ; C)

    *triangle(A ; B ; C)
    *right-angle(B ; A ; C)
)


The drawing engine determines the position of C from the constraints.


Example: circle and tangent
---------------------------

Code:

*draw(
    *point(O = 0, 0)
    *circle(O ; 3)

    *point(A)
    *on-circle(O ; 3 ; A)

    *line(O ; A)

    *point(B)
    *perp(O ; A ; A ; B)

    *line(A ; B)
)


Rendering
---------

The geometry system is responsible for calculating the positions of points
and geometric objects.

The final drawing can then be rendered using Typst and a drawing package
such as CeTZ.

The user should normally work with geometric relationships instead of raw
coordinates.

Coordinates are still available when precise positioning is required.


Design principle
----------------

Simple drawings should require very little code.

Example:

*draw(
    *triangle(A ; B ; C)
    *right-angle(A ; B ; C)
)

The system should automatically handle:

- Point positioning
- Label positioning
- Line and circle geometry
- Intersection calculation
- Angle markers
- Right-angle markers
- Equal-length markers
- Parallel markers
- Perpendicular markers
- Basic measurements

Manual coordinates should be an option, not a requirement.


Friendly alternatives
---------------------

The classic syntax above keeps working. These shortcuts are accepted
too (same output, less typing):

Commas work like ";" (when ";" is absent, "," separates args):

*frac(2, 3)  =  *frac(2 ; 3)
*pow(x, 2)   =  *pow(x ; 2)
*line(A, B)  =  *line(A ; B)

When ";" is present it wins, so *frac(100,000 ; 2) keeps 100,000
as one number. *point(A = 0, 0) never splits on "," (x, y coords).

Aliases (starred):

*fraction(...) = *frac(...)
*power(...)    = *pow(...)
*cbrt(x)       = *root(3 ; x)
*absolute(...) = *abs(...)
*summation(...) = *sum(...)
*product(...)   = *prod(...)
*limit(...)     = *lim(...)
*integral(...)  = *int(...)

Assignments:

let <x> = 5   =  <x> = 5
let x = 5     =  <x> = 5
var x = 5     =  <x> = 5
*define x = 5 =  *define(x = 5)

Document structure:

# Title   ->  = Title (heading)
## Sub    ->  == Sub
### Sub   ->  === Sub
- item    ->  Typst list (not escaped)
+ item    ->  Typst list
1. item   ->  Typst enumeration
= Title   ->  Typst heading (not escaped)

Document title:

*doc_title(My Lesson) sets the centered title + PDF metadata.
Aliases: *doc-title, *doctitle, *title. Control line (consumed,
last wins). Variables, calc, math and symbols work inside.
Default when absent: Easy Math Document.

Document font:

*doc_font(DejaVu Sans) sets the body font family.
*doc_font(DejaVu Sans ; 14pt) also sets the size (bare numbers
mean points: *doc_font(DejaVu Sans ; 14)). Aliases: *doc-font,
*docfont. Control line (consumed, last wins). Default when absent:
Typst default at 12pt. Note: the build ignores system fonts, so use
a family bundled with Typst.

Equality:

a == b  ->  a = b (single equals; === and !== still map to
their own symbols first).

Unknown *command(...) suggests the closest known command.

Tables and matrices
-------------------

*table(cell ; cell | cell ; cell)
*matrix(1 ; 2 | 3 ; 4)
*mat(...) = *matrix(...)

Rows split on "|" (top-level only, not inside ()/ {}/[]/"...").
"||", "|-", "-|", "|->" never split (use *mid for literal |).
Cells split on ";" (or "," when no ";" in that row, same as *frac).
Variables, calc, math commands and symbols work inside cells.
*table -> Typst #table (text mode), *matrix -> $mat(...) (math mode).
Multiline blocks (*table( ... ) / *matrix( ... )) join lines with "|";
empty rows are ignored, ragged rows warn and pad ([] for tables,
0 for matrices). Matrices work inside \ ... \; tables do not.

Function plots
-------------

*plot(expression ; xmin ; xmax)

*plot(x^2 ; -5 ; 5)
*plot(sin(x) ; -10 ; 10)
*plot(1/x ; -10 ; 10)

Numerically evaluated (1000 samples, NumPy) and rendered with
Matplotlib to <stem>-plot-<n>.svg, embedded as
#image("...svg", width: 80%). calc-style syntax: + - * / % ^,
x, pi/e, sin cos tan cot sec csc arcsin arccos arctan sinh cosh
tanh coth sqrt cbrt log (base 10) ln abs exp.
Non-finite values skipped; curves break across large jumps so
1/x draws no vertical line. Errors emit [Plot Error: ...] inline
and never abort the build.

Export (CLI / editor File -> Export As):

easy-math-lang doc.ezmath          -> doc.pdf
easy-math-lang doc.ezmath out.png  -> PNG image(s)
easy-math-lang doc.ezmath out.svg  -> SVG image(s)
easy-math-lang doc.ezmath out.html -> HTML
easy-math-lang doc.ezmath out.typ  -> Typst source only
easy-math-lang --format png --ppi 300 doc.ezmath -o hi.png
easy-math-lang --list-formats

Multi-page PNG/SVG writes stem-1.ext, stem-2.ext, ... (or {p}
pattern when given).
